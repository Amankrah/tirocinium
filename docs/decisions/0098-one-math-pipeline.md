# 0098: one math pipeline, and it renders what the source says

A review of the LaTeX rendering found five ways a student could read a different formula from the stored one, or read the source itself, and they are fixed together because they share a cause: the pipeline had grown on four surfaces separately. The renderers now take their plugin lists, KaTeX options, URL rule, and a delimiter pass from one module (`components/reading/markdown.ts`), so the reading body, its client twin, the import review, and the transcription preview cannot drift; the two previews had been running bare KaTeX without the subscript, fraction, or table handling. That delimiter pass exists because the transcription prompts ask for `\( \)` and `\[ \]`, which remark-math does not read and markdown takes for escaped brackets, so a student checking the reading of their own handwriting saw "(m_1 + m_2)"; it also gives a `$$` formula written alone on one line its own display block, which is what the variant prompt and the unfold's splitter already meant by it and which remark-math otherwise sets inline. Like the chain break (decision 0086), it is a rendering decision: the stored text and what the tutor is sent are unchanged, and we normalise on the frontend rather than amending the prompts because readings already stored carry the brackets. The native-script pass now rewrites only a script that is plain text, since flattening $e^{-\frac{Q}{RT}}$ to "e−RTQ" swapped one misreading for a worse one; the chain break now applies to display math only, as 0086 always said, and treats `\left( \right)` as a group so it no longer breaks inside one and leaves KaTeX printing red source. KaTeX is pinned to one version with a pnpm override, because rehype-katex had been producing HTML with its own 0.16 while the page loaded the 0.18 stylesheet, whose class names differ (`base` became `katex-base`), and the post-processors read that HTML's structure. Untrusted text reaches KaTeX, so `trust` stays off and `maxSize` caps every size a source can ask for at ten em. Flagged rather than resolved: a PDF import confirmed into a case study keeps its `\( \)` in the stored body, which the reading surfaces now render correctly, but the backend passes that see the body (auto-parameterization, variant generation) still read the brackets as written, and whether to normalise at confirmation is the backend's call.
