# 0101: the project marketplace reaches the prototype

The project marketplace of decision 0100 was one page, and the BREE 216 teaching prototype it descends from (`BREE 216 Marketplace.html`) is a whole shop, so it now carries the prototype's surfaces under `/marketplace`: a front page with the supplier directory, the lines projects most often start from and three comparisons worth making; a page per supplier with its trading terms and minimum-order note, and ticked categories, ticked attributes and the prototype's sorts (price per kilogram, density, yield strength) as a plain GET form that works with no script; a page per line with its price ladder, price per kilogram and per litre, data sheet, fabrication route and derived indices; the briefs and a page per brief that loads its candidates into the comparison or the quote; search across names, descriptions and suppliers; the guide to building a quote; the price sources; a comparison tray with the full comparison; a request for quotation; and the quotation itself, printable and copyable as a table. The basket and the tray live in the marketplace layout, so they survive every navigation inside it and nothing outside it, which is decision 0100's "nothing is kept" made literal. The server gained what the pages needed and nothing else: repeated `category` and `tag` filters, a `sku` list for reading a brief or a featured set in order, the wider search, the three sorts with missing figures last, related lines, `kg_per_unit`, and the line's derived indices from the same functions the comparison uses so the two cannot disagree; the comparison's first row is now named for its prices ("List price" here, "Your price" on a case study). The guide, sources, featured lines and preset comparisons are editorial content for one catalogue, kept in the web surface rather than in a new catalogue version (which would have stranded every course pinned to v1), shown only when the catalogue id matches, and pinned by a test that reads the shipped catalogue: that test refused two of the prototype's own figures (a 2.9× specific-strength ratio the data puts at 3.2×, and per-square-metre prices for lines sold per sheet), which are corrected or dropped. Four things in the prototype are deliberately not carried over: the name and group fields on its request form, because a student here is an anonymous seat; its "verified purchase" reviews attributed to named people, which are fabricated testimonials; its supplier star ratings, which are the same thing in aggregate; and its palette, gradients and colour-coded best cells, because the specification (milestone 10.6) builds on the token layer, so a best cell is labelled "best" in words instead. Building it surfaced two defects outside it, both fixed: the shared quotation body listed the volume discount and the cutting charge as if they adjusted a goods figure that already included them, so the rows on the case-study quotation did not add up (they now read materials after discount, then cutting, and a test sums them to the total); and a constant exported from a `"use client"` module reached a server page as a reference rather than a number and silently emptied the brief page's comparison, the same trap as `FIG_PREFIX` in decision 0066, now a plain module. The surface was walked end to end in a real browser against a seeded backend, with axe WCAG 2.2 AA clean on every page and no horizontal overflow at phone width; the marketplace navigation scrolls as one row on a phone after the first walk showed it filling the screen. Still open: a Playwright journey for it in CI, and whether a basket should survive a reload.
