# 0100: a project marketplace outside any case study

The marketplace of decision 0076 exists only inside a case study: every route hangs off a variant, a price is a function of that variant's seed, and a quotation is stored in the course shard so a submission can cite it and the tutor can press on it. A student doing a design project has none of that to hang it on (the catalogue's sixteen briefs were written for exactly those projects) and still needs to price the materials, so `/marketplace` now stands beside it, and the guides, silent on a marketplace altogether, are silent here too. Three choices define it, each made by the product owner on 2026-10-21. Access is any seat, from any course, whether or not that course prices materials, because the seat is the platform's one way a student exists and a new identity for projects would be a second answer to "who is this" with nothing gained; the catalogue is the seat's course pin when there is one, so the figures agree with what the course teaches from, and otherwise the newest shipped catalogue. Prices are the catalogue's list prices, the same for every student, which deliberately reverses 0076's rule that a list price is "never what a student is quoted", for this surface only: 0076's moving prices protect a graded quotation from being copied, and a project quotation is not graded, is often shared across a team, and is truer to a supplier's price list when it does not move. The case-study marketplace is unchanged and still seeded. And nothing is stored: the server prices the basket on request (`compute_quote`, `compare` and `advise` are the case-study marketplace's own, called with list prices) and hands the quotation back for the student to print, so there is no basket to resume, no quotation to cite in a submission, and no row anywhere, which a test asserts against the shard's quote and RFQ tables. In place of an issued number the quotation carries a reference digested from the catalogue, the day and the basket, so the same basket prepared twice on one day prints the same reference and a student can cite it in a report and reproduce it without the platform keeping anything. To share rather than copy, the line, supplier and filtering logic moved from `routes.py` into `app/marketplace/listing.py` as pure functions over (catalogue, prices), and on the web side the catalogue browser, line card, comparison table, RFQ panel and quotation body moved into the private `app/(student)/_marketplace/` folder, used by both surfaces; the case-study browser now receives its actions already bound to the variant. What prints is a fixed copy of the quotation with its reference, dates and price basis, and the shell header and everything else on the page are hidden from the printer. The way in is the student header, which now carries two links, Course and Marketplace, on every student page, with the current one marked (`aria-current`); the shell takes the section as a prop defaulting to the course, so it stays a Server Component with no script. Open: a Playwright journey for this surface, and whether a project basket should survive a reload in the browser, which nothing here does.
